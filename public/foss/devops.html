DevOps y ramas

Una rama por modelo

RamaTocaModelo
dev/clasemodelos/clase/Materialismo filosófico (Gustavo Bueno) sobre Oasis/SSB
dev/colectividadesmodelos/colectividades/Colectivizaciones 1936-37 frente a la República Pura
dev/res_publicamodelos/res_publica/República Pura (Trevijano) sobre Oasis/SSB
maintodo lo demás + public/ + data/integración y publicación

Cada rama dev/<modelo> solo modifica su carpeta, así main las integra con git merge --no-ff sin conflictos. El generador, las plantillas, la documentación y public/ se tocan únicamente en main.

Ciclo operativo

# en la rama del modelo
git checkout dev/<modelo>
#   … añadir drafts/draftvN.md, fichas en revision/, actualizar 00-indice.md …
modelador indice --modelo <modelo>        # línea «Draft vigente»
git commit

# en main
git checkout main
git merge --no-ff dev/<modelo>
modelador build && modelador check && pytest
git add public data && git commit -m "build: public/ (+<modelo>)"
git push origin main dev/<modelo>

GitHub Pages

El workflow .github/workflows/pages.yml no construye nada: sube el public/ commiteado en main. Pages debe tener como origen GitHub Actions. La web sirve en https://alephscriptorium-eng.github.io/modelador-redes/; los ficheros fuente se enlazan a github.com (blob y raw) y se empaquetan en zip por modelo.

Agentes

llms.md es el contrato de onboarding para cualquier LLM que trabaje en el repo: reglas de ramas, regla del draft vigente, qué no hacer. También en crudo: https://github.com/alephscriptorium-eng/modelador-redes/raw/main/llms.md.
