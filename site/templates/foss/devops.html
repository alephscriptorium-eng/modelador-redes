Cada rama dev/<modelo> solo modifica su carpeta, así main las integra con git merge --no-ff sin conflictos. El generador, las plantillas, la documentación y public/ se tocan únicamente en main.

Ciclo operativo

# en la rama del modelo
git checkout dev/<modelo>
#   … añadir drafts/draftvN.md, fichas en revision/, actualizar 00-indice.md …
modelador indice --modelo <modelo>        # línea «Draft vigente»
git commit

# en main
git checkout main
git merge --no-ff dev/<modelo>
modelador build && modelador check && pytest
git add public data && git commit -m "build: public/ (+<modelo>)"
git push origin main dev/<modelo>

GitHub Pages

El workflow .github/workflows/pages.yml no construye nada: sube el public/ commiteado en main. Pages debe tener como origen GitHub Actions. La web sirve en {{ provenance.pages_url }}; los ficheros fuente se enlazan a github.com (blob y raw) y se empaquetan en zip por modelo.
